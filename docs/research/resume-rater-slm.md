# Local model research for the resume rater

**Researched:** 2026-10-19
**Scope:** Local models for comparing candidate resumes with one job posting and a shared, manager-approved rubric; producing evidence-grounded reports and a ranked list.

## Recommendation

The closest purpose-trained model I found is **ConFit v3**, a Qwen3-8B model fine-tuned specifically for resume/job reranking. It is promising research, but it is not a ready-to-use dependency for this feature: the paper evaluates listwise ranking against historical accept/reject outcomes, while this application needs criterion-level evidence, stable weighted scores, and cited resume passages. The authors' public repository provides training and inference code, but I found no distributable ConFit v3 tuned checkpoint or checkpoint license in the official artifacts checked. Its recruiting data is described as proprietary. The paper also explicitly warns about inherited bias and advises against real-world use without debiasing. [ConFit v3 paper](https://arxiv.org/abs/2605.09760), [authors' code repository](https://github.com/jasonyux/ConFit-v3)

For an implementation-ready local default, use **`qwen3.5:9b-q4_K_M`** if the target Mac has enough memory. Ollama lists it at 6.6 GB with a 256K context; Qwen's model card lists Apache-2.0 and 9B parameters. These make it a capable current general model with a practical quantized Ollama build, but its published benchmarks do not establish resume-rating accuracy or fairness. [Ollama Qwen3.5 tags](https://ollama.com/library/qwen3.5/tags), [Qwen3.5-9B model card](https://huggingface.co/Qwen/Qwen3.5-9B)

If memory is tighter, evaluate **`qwen3.5:4b-q4_K_M`** as a smaller alternative (Ollama lists a 3.3 GB build and the same 256K context). The best fallback among the application's existing configured models is **`qwen2.5:7b`**: it is already the default for document analytics and is available for RAG; Ollama lists the Q4_K_M build at 4.7 GB and 32K context. `llama3.1:8b` is another configured option and has 128K context, but this application already uses Qwen2.5 for document analysis. The repository configuration is in [document analytics](../../backend/app/prompts/document/document_analytics/agent.json) and [chat](../../backend/app/prompts/chat/chat/agent.json). The listed models are configured choices; this research did not verify which weights are currently downloaded on a particular machine. [Ollama Qwen2.5 tags](https://ollama.com/library/qwen2.5/tags), [Ollama Llama 3.1 tags](https://ollama.com/library/llama3.1/tags)

ConFit v3's paper uses a two-stage design: a retrieval model first narrows the pool, then a fine-tuned Qwen3 re-ranks candidates in sliding windows. Its evaluated ranking data pairs resumes and jobs with acceptance labels; it notes that an unlabelled applicant may simply not have applied. This makes it a useful research reference for ranking, but a poor source of ground truth for a transparent evidence rubric. Its authors also state the model can inherit demographic bias and discourage real-world use without debiasing. Those limits matter more here than the reported benchmark gains. [ConFit v3 paper](https://arxiv.org/abs/2605.09760), [ConFit v3 repository](https://github.com/jasonyux/ConFit-v3)

## Implementation guidance

- Let the model identify relevant requirements, assess each criterion, attach exact resume evidence, and draft explanations. Compute the 0–100 weighted score in application code from the approved rubric. This keeps the shared rubric and score arithmetic consistent across candidates.
- Request a JSON Schema-constrained response through Ollama and validate it with the app's Pydantic schemas. Schema-constrained output improves format consistency; it does not verify that a quoted passage is real or that an assessment is fair. [Ollama structured outputs](https://ollama.com/blog/structured-outputs)
- Verify every evidence quote against the extracted resume text. If extraction, quote verification, or schema validation fails, keep that candidate unranked and mark the assessment for attention.
- Use the same posting and rubric for each independently assessed candidate. Strip or mask names and other non-job-related personal details before assessment, retaining a separate mapping for manager display. Do not score school or employer prestige on its own. Debiasing prompts are not a substitute for evaluation.
- Treat ratings as decision support. Measure evidence accuracy, false missing-requirement flags, score/rank consistency across runs and harmless resume-format changes, and group effects where lawful data and consent permit. Record the model version and rubric version for each result.

NIST's AI Risk Management Framework calls for validity and reliability testing, explaining model limits, and evaluating and documenting fairness and bias throughout an AI system's lifecycle. The EEOC states that employment tests and selection procedures should be job-related and validated for their intended use, and that neutral procedures can still have disparate impact. A human review step is useful product design, but it does not by itself validate a hiring assessment or settle compliance questions. [NIST AI RMF Measure function](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/), [EEOC Employment Tests and Selection Procedures](https://www.eeoc.gov/laws/guidance/employment-tests-and-selection-procedures)
